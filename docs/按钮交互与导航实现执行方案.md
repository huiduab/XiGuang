# 隙光按钮交互与导航实现执行方案

## 1. 文档目标

当前版本已经完成分享面板收藏、平台识别、URL 去重、Room 本地存储和收藏分类首页，但首页的大部分按钮仍是视觉占位。本阶段的目标是把现有界面从“可以收藏”推进到“可以进入、查找、阅读和管理收藏”的可用版本。

本阶段不包含自动抓取 X、微博、小红书或抖音，也不包含后台订阅刷新。订阅系统应在收藏阅读闭环完成后实施。

本项目采用 Vibe Coding 推进方式，不使用“开发日”或固定工期估算。每次只执行一个能够独立编译、安装和验收的批次；当前批次通过后，再进入下一批。

## 3. 页面与导航结构

应用采用单 Activity 和 Navigation Compose。所有主要页面共用同一套底部导航状态，详情页和搜索页覆盖底部导航。

```text
MainActivity
└─ XiguangApp
   ├─ 今日 Today
   ├─ 项目 Projects
   ├─ 收藏 Collection
   │  ├─ 收藏根页
   │  ├─ 分类内容列表
   │  ├─ 收藏详情
   │  ├─ 搜索
   │  └─ 收藏夹管理
   └─ 设置 Settings
```

建议路由：

```text
today
projects
collection
collection/list?folderId={id}
collection/list?platform={platform}
collection/detail/{collectionId}
collection/search
collection/folders
settings
```

导航要求：

- 底部导航重复点击当前页面时，不重复创建页面。
- 从详情页返回时保留原列表的筛选条件和滚动位置。
- Android 系统返回键按照页面栈返回。
- 分享保存页面继续使用独立 `ShareReceiverActivity`，不并入主导航栈。

## 4. 分阶段实施计划

### 执行批次 A：建立真实导航

实施内容：

1. 引入 Navigation Compose。
2. 新建应用级路由和导航图。
3. 将 `MainActivity` 从直接显示 `CollectionRoute` 攦为显示 `XiguangApp`。
4. 将底部导航按钮改成回调参数，连接“今日、项目、收藏、设置”路由。
5. 为尚未完成业务的页面提供明确空状态，禁止按钮点击后无反应。

验收标准：

- 四个底部按钮都能切换页面。
- 页面选中颜色与当前路由一致。
- 返回键行为正确。
- 页面切换过程中没有闪退和重复页面。

### 执行批次 B：分类列表与收藏详情

实施内容：

1. 点击收藏夹分类，按 `folderId` 查询并显示收藏列表。
2. 点击平台分类，按 `platform` 查询并显示收藏列表。
3. 收藏列表显示标题、平台、保存时间、内容类型和已读状态。
4. 点击收藏条目进入详情页。
5. 详情页显示标题、分享文字、网址、平台、收藏夹、备注和保存时间。
6. 网址支持两种打开方式：
   - 默认在应用内阅读页打开。
   - 菜单中选择外部浏览器打开。
7. 图片和 PDF 第一版调用系统可用应用查看；后续再增加专用阅读器。

验收标准：

- 每个分类显示的数量与列表实际数量一致。
- 点击任何列表条目都能看到对应详情。
- 无网址、纯文字、图片和 PDF 收藏不会导致闪退。
- 无可用外部应用时显示错误提示。

### 执行批次 C：搜索和收藏管理

实施内容：

1. 搜索标题、网址、分享文字和备注。
2. 支持按平台、收藏夹、内容类型和已读状态筛选。
3. 支持编辑标题和备注。
4. 支持移动到其他收藏夹。
5. 支持删除收藏，并提供二次确认。
6. 支持标记已读和恢复未读。
7. 长按列表条目进入多选模式，第一版支持批量移动、标记已读和删除。

数据库调整：

```text
collections
├─ is_read       INTEGER NOT NULL DEFAULT 0
├─ read_at       INTEGER NULL
└─ archived_at   INTEGER NULL
```

Room 数据库由版本 1 升级到版本 2，必须提供正式 Migration，禁止使用破坏性重建，确保现有收藏不会丢失。

验收标准：

- 搜索结果随输入更新。
- 编辑和移动后，列表与分类数量立即更新。
- 删除后数据库中不再存在该条记录。
- 升级安装新 APK 后，旧版本收藏仍然存在。

### 执行批次 D：收藏夹管理

实施内容：

1. 新建一级收藏夹。
2. 在一级收藏夹下新建二级收藏夹。
3. 重命名和调整顺序。
4. 删除空收藏夹。
5. 删除非空收藏夹时要求选择：
   - 将内容移动到“未整理”。
   - 移动到其他收藏夹。
   - 取消操作。
6. 分享保存页同步显示新建后的收藏夹结构。

限制：

- 第一版最多支持二级结构。
- 同一父级下不允许重名。
- 不实现任意深度递归目录。

### 执行批次 E：“今日、项目、设置”最小可用版

“今日”页面：

- 显示未读收藏。
- 显示今天新增内容。
- 支持“随机读一条”。
- 阅读完成后标记已读并从主要列表淡出。

“项目”页面：

- 第一版支持创建、重命名和删除关注项目。
- 项目可以关联收藏夹和多个来源网址。
- 暂不自动抓取；先作为关注主题与来源目录。
- 后续订阅模块直接复用项目数据。

“设置”页面：

- 深色模式：跟随系统、浅色、深色。
- 默认打开方式：应用内、外部浏览器。
- 通知总开关默认关闭。
- 数据统计：收藏总数、未读数和数据库占用空间。
- 关于页面：版本号、构建类型和隐私说明。

验收标准：

- 三个页面不再是占位页。
- 设置修改后重启应用仍然生效。
- 通知默认保持关闭。

### 执行批次 F：质量验证与 APK 交付

测试范围：

- DAO 查询、更新、删除和数据库迁移测试。
- 收藏夹与平台筛选测试。
- 搜索测试。
- 已读状态测试。
- Compose 导航与主要按钮 UI 测试。
- 分享保存回归测试。
- API 23 与 API 37 兼容检查。

云端构建必须通过：

```text
testDebugUnitTest
lintDebug
assembleDebug
```

交付物：

- 可安装 Debug APK。
- GitHub Actions 成功记录。
- 数据库 Migration 文件和 Schema。
- 更新后的功能清单与测试记录。

## 6. Vibe Coding 执行规则

每个批次都按照同一循环执行：

```text
选择一组相关按钮
→ 明确点击后的可见结果
→ 修改最少数量的文件
→ 云端测试、Lint、构建 APK
→ 手机上验证点击路径
→ 记录结果
→ 再进入下一批
```

每一批必须满足：

- 不同时开发无关功能。
- 不为了“以后可能需要”提前建立复杂抽象。
- 不保留点击后无反馈的按钮；功能未完成时必须显示明确空状态或说明。
- 数据层改动必须有 Room Migration，不能清空用户收藏。
- 当前批次构建失败时先修复，不带着失败进入下一批。
- 每次提供新的 APK，让用户能够直接体验并提出下一轮调整。

## 7. 推荐执行顺序

```text
A 导航与底部按钮
→ B 分类列表与详情
→ C 搜索、已读、编辑、移动、删除
→ D 收藏夹管理
→ E 今日、项目、设置
→ F 全量测试与 APK
```

不要优先做动画、复杂网页解析或自动订阅。首先保证每个现有按钮有明确结果，并完成“收藏—找到—打开—读完—整理”的核心流程。

## 8. 阶段完成定义

满足以下全部条件才算本阶段完成：

- 正式页面不存在空点击事件。
- 四个底部导航入口均可用。
- 收藏夹和平台分类均可进入内容列表。
- 收藏可以打开、编辑、移动、标记已读和删除。
- 搜索可以找到已保存内容。
- 可以创建和管理二级收藏夹。
- 数据库升级不丢失旧收藏。
- 单元测试、Lint 和 Debug APK 构建全部通过。
- 在真实 Android 手机上完成一轮分享、保存、阅读、整理回归测试。
